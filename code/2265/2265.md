# C++23: a recursive lambda and an iterative solution with branchless loop bodies

This is a very simple problem, but you can still learn a few tricks here. The
first one is C++23's deducing this,
which lets a lambda call itself. That is neat because we can write the lambda
and invoke it straight away, without a separate helper function or a named
variable to hold it.

Both solutions use the same idea: each subtree gives us its sum and its node
count. Once we have those, checking the root of that subtree is just
`sum / count == node->val`. Since the values are non-negative, integer division
gives the rounded-down average required by the problem.

## 1. Recursive lambda

`this auto&& f` gives us a reference to the lambda itself, so recursive calls
look like `f(x->left)`. We capture the answer by reference and return a small
pair of values: `s` for the sum and `c` for the count.

A null node returns `{0, 0}`. For any other node, we combine its own value with
the results from both children, then check the average. The explicit `-> P`
return type lets us call the lambda recursively before its return type could
otherwise be deduced.

```cpp
class Solution {
public:
    struct P {
        int s{}, c{};
        inline void add(P x) {
            s += x.s;
            c += x.c;
        }
    };
    int averageOfSubtree(TreeNode* x) {
        int r = 0;
        [&r](this auto&& f, TreeNode* x) -> P {
            P p{};
            if (x) {
                p.add(P{x->val, 1});
                p.add(f(x->left));
                p.add(f(x->right));
                r += ((p.s / p.c) == x->val);
            }
            return p;
        }(x);
        return r;
    }
};
```

This takes **O(n) time** and **O(h) extra space** for the recursive calls, where
`h` is the height of the tree.

## 2. No recursion

The second solution shows how we can do it without recursion at all.

This is useful for very deep trees: a long chain of nodes can exhaust the call
stack with recursive DFS. Here, the frames live in a static array, so traversal
depth does not grow the call stack. The array still needs enough room for all
the nodes.

First, we put the nodes into an array and remember each node's parent index.
Every child is placed after its parent, so walking the array backwards gives
us exactly what we need: all descendants are processed before their ancestors.
We check each node, then add its sum and count to its parent.

There is another small trick in the first loop:

```cpp
for (const auto* child : {f.x->left, f.x->right}) {
    st[top + 1] = {child, i};
    top += !!child;
}
```

We always write the candidate child, but only advance `top` if the pointer is
non-null. `!!` turns the pointer into a boolean, which contributes either `0`
or `1`. A null child stays outside the active range and its slot can be
overwritten by the next candidate. No `if` is needed.

Index `0` is a dummy parent for the root. That lets the second loop add every
node's totals to its parent without treating the root separately. We also
reserve one spare slot at the end for those unconditional child writes.

```cpp
#include <initializer_list>

struct Frame {
    const TreeNode* x{};
    int parent{}, s{}, c{};
};

class Solution {
public:
    // Up to 100,000 nodes, plus a sentinel and a spare write slot.
    inline static Frame st[100'002];

    int averageOfSubtree(const TreeNode* root) noexcept {
        int top = root != nullptr, r = 0;

        st[0] = {};
        st[1] = {root};

        for (int i = 1; i <= top; ++i) {
            Frame& f = st[i];
            f.s = f.x->val;
            f.c = 1;

            for (const auto* child : {f.x->left, f.x->right}) {
                st[top + 1] = {child, i};
                top += !!child;
            }
        }

        while (top) {
            const auto& [x, parent, s, c] = st[top--];
            r += s / c == x->val;
            st[parent].s += s;
            st[parent].c += c;
        }

        return r;
    }
};
```

The two passes still take **O(n) time** and use **O(n) frame entries**. This
version reserves a fixed buffer of 100,002 entries in static storage, so that
buffer does not live on the call stack.
